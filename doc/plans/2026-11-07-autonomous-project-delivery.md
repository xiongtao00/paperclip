# 自主交付执行能力补齐

分支 `workflow-improve-261107`，基于 `prod`。本轮把出门清单暴露的四个执行缺口收敛到项目通用工具。

| 缺口 | 所属实现 | 可验证结果 |
|---|---|---|
| Runner Chromium 启动失败 | `native-runtime/project-browser.ts` | 同一宿主预检、建页和点击可用；原生运行按授权公司开放工具 |
| 附件可校验但无法看图 | `runner-task-attachments.ts` 与 Codex 图片结果处理 | 当前任务 PNG 校验后进入模型视觉输入；跨任务和撤销权限被拒绝 |
| 验收没有常驻页面，固定端口冲突 | 固定 Git 快照、自动分配 loopback 端口 | 验收人自行打开；无须启动项目服务；工作区未提交变动不影响固定版本 |
| 能 HTTP 访问但不能操作 | `project_browser` 原生工具 | 页面树、图片、点击、输入、按键、视口与刷新在一个运行内完成 |
| 受管结果缺件或接续失败没有接手人 | `managed-host-execution.mjs` 可选恢复负责人 | 原项目中幂等创建 CTO 修复任务，保留执行收据及防重放 |
| 指令要求与实际工具脱节 | 版本化员工指令更新脚本 | 八岗位读回核验；预检、设计、体验与功能签核、具体修复责任都有操作入口 |

服务端项目浏览器拥有进程和临时页面生命周期；任务附件模块拥有原件读取与归档；Codex 驱动仅把规范图片结果映射到已安装 app-server 协议的 `inputImage`。既有任务权限、运行锁、工具回执和存储继续作为授权与恢复的权威来源。

XHZ-29 已由 QA 完成实际工具验收。开发侧回归覆盖原图、权限与恢复，并完成宿主真实浏览器验证。

验收条件为独立员工能在原生会话中预检、查看固定版本、实际操作并读取自己任务中的原始 PNG，且无需操作员开页面、搬图片或代转述。开发侧自检、员工验收及未覆盖能力分别记录。

部署边界、操作员配置、员工工作方式与支持范围见 [本机项目浏览器与自主交付](../project-browser-agent-workflow.zh-CN.md)。后端、外部服务、模型和实机按项目具体能力规划；出现超出授权的需求时保留董事会决策入口。

## 验证记录

- 服务端相关回归65项、Codex图片与动态工具回归32项、受管执行器回归10项通过。服务端类型检查、Runner TypeScript构建、模块边界和地图结构检查通过。
- XHZ-29员工工具验收通过，固定产品提交为f7265ba8c2fe883abca54a1e9eb27665bd00611e。初次调试发现并修复publishDir点号规范化及Codex Code Mode图片项丢失两处实际兼容问题。
- 调试时曾在员工运行中触发源码热重载，运行因进程身份无法重新确认而终止。核对该测试运行的进程组并停止后，通过平台幂等Retry恢复，最终由原QA签核。后续部署须等活跃运行结算，避免以开发热重载承载无人值守生产任务。
- 全量agent-preflight在本机因缺少Cargo未完成。本轮改动未涉及Rust；已单独完成Runner TypeScript构建，并重建上游更新后过期的plugin-sdk产物，服务端类型检查通过。全仓Rust发布构建未验证。

## 开工澄清补充

CEO在实现前组织岗位评审，统一提出产品、代码位置、资源与授权问题，通过真实问答卡等待用户并自动接续。完成记录后再发布可开工结论。岗位指令和[开工流程](../project-kickoff-workflow.zh-CN.md)同步维护。完整项目验证包含这一阶段，真实用户答复不能由测试操作者代签。
