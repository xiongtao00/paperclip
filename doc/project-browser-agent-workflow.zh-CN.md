# 本机项目浏览器与自主交付

本功能面向已授权公司的本地 Codex Runner，为静态 Web 产品提供预检、隔离预览、实际页面操作和原图视觉输入。执行入口在 Paperclip 服务端，员工通过原生工具调用，应用进程、端口和浏览器不再依赖董事会临时启动。发布前仍由独立岗位签核。

## 开工与验收

1. CEO 先按[开工澄清流程](project-kickoff-workflow.zh-CN.md)组织岗位评审、汇总问答并确认需求、资源、工作区和授权，再指定 CTO 负责环境、QA 负责功能、PM 负责体验。PM 与设计在实现前确定核心用户任务、视口与设备范围、空态、失败反馈和恢复方式。
2. CTO 或 RE 在实际任务中调用 `project_browser`，`action=preflight`。它验证同一宿主 Chromium 可以建页、点击和生成 PNG。随后针对首个提交调用 `open`，验证产品快照与 loopback。预检与产品通过分别记录。
3. 开发交完整的 40 位提交 SHA。项目的主要工作区必须绑定本地仓库，目录位于公司授权根目录中。服务从该仓库读取提交里的静态文件，使用内存快照提供页面，不执行仓库脚本。
4. 独立验收人在自己的任务里调用 `project_browser`，指定 `action=open`、`commit`，构建输出在子目录时指定 `publishDir`。首次打开分配随机空闲端口。无需启动固定端口的开发服务器。
5. 每次观察和操作返回当前页面树及 PNG 视觉输入，并将原图附到该任务，附带 SHA-256、提交身份和视口。验收人根据实际观察决定下一步，用页面树中的精确 `role` 和 `name` 点击、输入或按键。可以调整视口、刷新、观察和关闭。
6. 检查已有附件时先 `list_task_attachments`，再 `read_task_image`，传入 `attachmentId` 和 `expectedSha256`。PNG 经存储哈希校验后作为 Codex 图片输入返回。Code Mode 中先解析工具返回的 JSON 字符串，再用 `image(value.image_url)` 展示；只打印状态和哈希等元数据。读取原件不会重新执行功能测试。
7. QA 和 PM 分别记录实际功能与体验结论。CEO 核对两者并收口。设备范围以项目约定为准，手机视口模拟和实机分别记录。

## 运行与恢复边界

浏览器按原生运行隔离，最多十分钟，运行结束释放页面、浏览器、监听端口及临时目录。下一运行重新打开固定版本并明确新会话状态。同一调用由既有持久工具回执防重复，未知结果先观察，不自动重放点击。每次动作前后复核原任务执行权限，停止、换人或撤销权限后不再把图片交给原员工。

`open` 或 `preflight` 的环境失败会用原任务的正常权限创建唯一 CTO 修复子任务，并在持有原任务锁时追加依赖，保留其他阻塞关系。修复完成后沿用现有依赖恢复机制接续原验收人。当前员工本身是 CTO 或公司未设置唯一 CTO 时，返回具体错误，由该岗位按职责处理。

截图归档失败时保留已经完成的页面动作及实时图像，明确附件交付失败。员工应观察当前状态补交截图，不能重复该动作。原图读取保持当前任务、公司和运行的权限边界，不能用图片 ID 访问其他任务。

受管命令执行登记可选 `recoveryAgentId`，指向 CTO。预检失败、缺原件或无法确认审阅接续时，执行器在原项目创建带幂等键的修复任务，交给登记负责人，并在持久回执记录 `recoveryIssueId`。补交与重启继续沿用原执行收据。同一批准不会再次启动命令。新增恢复权限纳入 recipeHash，旧批准不会获得新权限。

出现具体环境错误时 CTO 接手唯一修复任务，回传修复证据并恢复原验收人。预算暂停、明确停止、独立任务依赖、未获准权限和产品失败保持各自的处理规则。需要扩大执行范围时，由团队准备可审阅的差量审批。

## 操作员安装

配置存放于 `~/.paperclip/project-browser.json`，也可使用服务端环境变量 `PAPERCLIP_PROJECT_BROWSER_CONFIG` 指定位置。配置只读取一次，更改后需在运行结算后重启服务。登记文件、模块与浏览器由操作员维护，项目代码不能修改它们。

```sh
node scripts/configure-project-browser.mjs \
  --company-id <公司UUID> \
  --root <该公司的专属项目父目录> \
  --playwright <已安装可信Playwright的绝对入口路径> \
  --chromium <宿主Chromium可执行文件绝对路径>
```

先审阅输出，再加 `--apply` 写入。允许重复的 `--root`、`--company-id` 参数。已有配置有差异时安装器拒绝覆盖，避免静默撤销或扩大其他公司的授权。禁止授权文件系统根目录。

应用员工指令的脚本使用受管指令 API、版本前置条件及读回校验。默认预览，指定 `--apply` 后生效。原有岗位内容保持在受管版本历史中。

```sh
python3 scripts/apply-project-browser-workflow.py \
  --company-id <公司UUID> --project-root <公司专属项目父目录> --apply
```

## 已支持范围与验收

当前浏览器入口支持提交中的 HTML、JS、CSS、JSON、图片和字体，或提交过的静态构建输出。每个快照最多 256 个文件、32 MiB，单文件最多 8 MiB。隐藏路径、node_modules、符号链接和其他文件类型不提供。只允许页面访问快照自身的 loopback，外部网络、子框架、WebSocket、下载及额外窗口受限制，浏览器不继承模型或宿主凭证。

图片视觉输入目前限本地 Codex，PNG 最大 300 KB，单会话累计图像最多 12 MiB。超限时 RE 提供可追溯的查看副本，保留原件。其他模型通道继续使用其原有工具。需要后端、未提交的构建、外部认证、真实模型或实机的项目，须由 CTO 在开工前提供相应受管环境；此静态入口不覆盖这些能力。

开发验证包含任务附件的当前权限、跨任务拒绝、哈希校验与归档，Codex 原生图片输出与既有动态工具回归，静态快照的版本冻结、隐藏文件和符号链接过滤，以及恢复任务的幂等分派。宿主验证覆盖真实 Chromium 预检、固定提交打开、点击、输入、视口切换及权限撤销。XHZ-29 已由 QA 实际签核通过，确认能看到勾选变绿、划线、未带数从3变2，以及未提交的雨伞输入，并对自己任务中的原始PNG校验后渲染。该结论覆盖工具资格；产品功能和体验仍沿用各自验收。
